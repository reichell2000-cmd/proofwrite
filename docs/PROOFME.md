# ProofMe — 기획과 구현 (2026-09-27)

## 학생의 작업 순서

1. 내 과제: 이 브라우저의 유효한 참여 권한에 속한 과제만 표시. 제출한 과제 / 피드백·다시쓰기 / 나의 과정으로 이동.
2. 과제 안내: 제목·설명·마감·상태·목표·교사의 내용 기준·다음 행동을 확인한 후 편집기로 이동.
3. 글쓰기: 이전 버전·한글 조합 묶음·자동 저장·기기 복구본을 유지. 상단 제출 준비 바로가기와 노력 기록 이동 링크.
4. 노력의 증거: 어려운 점 / 해본 일 / 달라진 점. 해본 일을 적거나 자료 1개 이상 첨부해야 제출 가능. 자료는 PDF·PNG·JPEG·WebP, 각 512KB 이하, 최대 3개. 서버에서 크기·서명·MIME 확인. 참고자료와 출처를 별도 입력.
5. 페이지 맨 아래 제출 확인: 제목·본문·노력 근거 확인. 선택 대목·성찰은 선택. 자동 저장은 제출과 다르며, 최종 이벤트와 자료가 서버에 저장된 후 문서 잠금. 서버 접수 시각과 접수번호 제공.
6. 제출 후 피드백 확인·다시쓰기: 기존 동작과 원문 보존 유지.

## 다섯 기준

| 기준        | 수집                      | 표시하는 관찰 자료                                                                               |
| ----------- | ------------------------- | ------------------------------------------------------------------------------------------------ |
| 생각의 증거 | 자동                      | 직접 입력·수정, 삭제 포함 입력, 버전, 멈춤, 전·후반 키 간격 변화                                 |
| 집중의 증거 | 자동                      | 60초 이내 간격으로 이어진 입력 구간 합계·최장 구간. 창 이탈·새 세션에서 끊음                     |
| 성실의 증거 | 자동                      | 첫/최근 작성, 작성일 수(한국 시간), 세션, 서버 제출 시각과 설정 마감 비교                        |
| 노력의 증거 | 작성자 제공               | 해본 일·어려움·변화 및 첨부한 메모·초안·자료                                                     |
| 나라는 증거 | 자동, 세부 리듬 선택 참여 | 같은 입력 방식의 타이핑 간격 비교. 이전 제출 기준이 있으면 이전 과제와, 없으면 과제 전·후반 비교 |

타이핑 리듬은 키 값/문자/코드를 보관하지 않고 간격·누른 시간·묶음 길이·수정 지연 등 시간 파생값만 저장한다. 일반 입력과 조합 입력은 별도 그룹. 0 초과 5초 미만 간격만 비교 표본으로 인정하며 현재 과제 최소 80개, 전·후반 비교는 각각 40개 이상이다. 이전 기준은 유효한 학생 쿠키로 접근 가능한 다른 과제의 제출본 중 같은 별명·동일 입력 방식·참여 동의·80표본 조건을 만족하는 가장 최근 기록의 요약값이다. 타인 별명만 알아서는 기준을 가져올 수 없다. 참여 해제 후 저장하면 현재 리듬과 기준 요약값을 삭제한다.

사고의 깊이·실제 집중·성격·본인 여부를 확정하지 않는다. 관찰된 자료의 유무와 교사가 볼 사실을 제시한다. 기존 임의 합계 점수는 화면에서 제거했다. `N/5 항목에 관찰 자료`는 성적이 아니라 데이터 가용성 표시다. 빠름·많은 삭제·오래 체류·밤샘 자체에 가점을 부여하지 않는다.

## 교사의 읽기

과제 생성 및 기존 과제의 ‘마감일·읽기 기준 설정’에서 주장·근거 / 관점 변화 / 자기 해석 / 정확성·논리 / 배움·적용을 선택한다. 기본 화면은 전체 글이다. 읽기 안내는 최종 문서에서 표현 단서가 있는 실제 대목을 최대 3개 뽑고, 선택 이유와 확인 질문을 표시한다. 앞뒤 맥락·전체 글로 이동하고 본문 인용을 피드백에 가져올 수 있다. 학생 선택 대목과 수정·붙여넣기 시점은 별도 근거로 유지한다.

이는 무료 규칙 기반 후보 선별이다. 의미를 이해해 우수성을 판정하는 AI 추천이 아니다. 표현이 없으면 일반 본문 대목을 제시한다. 글의 질 평가는 교사가 실제 글과 과제 목표를 읽고 수행한다.

## 호환성과 제한

기존 JSON에 없는 노력·마감·내용 기준·접수 시각·리듬 기준 필드는 선택 필드로 읽는다. 이전 제출본을 다시 쓰거나 가짜 접수 시각을 만들지 않는다. 기존 초안은 새 화면에서 노력 근거를 추가해 제출할 수 있다. 오래 열린 클라이언트는 새로고침이 필요할 수 있다.

기존 교사 비밀번호/학생별 7일 브라우저 권한을 유지하므로 계정 기반 기기 간 동기화·신원 인증이 아니다. 같은 브라우저·별명도 동일인을 보증하지 않는다. OS별 실제 한국어 IME·음성·보조입력 사용성 및 평가 타당성은 추가 현장 검증이 필요하다. 브라우저 이벤트는 조작 가능하며 개인정보 수집 범위는 편집기 안이다.

## 검증

단위 검증: 제출 필수 항목, 선택 대목 없이 제출, 노력 저장 충돌·이전 클라이언트 보존, 첨부 파일 검사, 최종 본문 읽기 후보, 입력 지속 구간·리듬 표본과 입력 방식 분리.

브라우저 검증: 기존 학생 작성·IME 이벤트·오프라인 복구·서식·재접속·피드백·다시쓰기, 신규 과제 안내·노력 첨부·재접속·하단 제출·과제 탭·교사 5축·내용 후보·접근 권한. 데스크톱과 모바일 화면 확인. 브라우저 합성 IME 이벤트 시험은 실제 OS IME 검증을 대신하지 않는다.
