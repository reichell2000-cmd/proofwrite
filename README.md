# ProofMe Pilot

**생각·집중·성실·노력·나라는 다섯 가지 과정 증거를 함께 읽습니다.**

교사가 과제를 만들고, 학생이 참여 링크에서 글을 작성·제출하며, 교사가 학생이 고른 대목과 작성과정을 읽는 독립적인 웹 애플리케이션입니다. AI 연결을 설정하지 않은 FREE 흐름은 기본 읽기 안내를 사용합니다. 선택적으로 교사용 AI 검토 초안을 연결할 수 있습니다.

## 실행

Node.js 22 이상이 필요합니다.

```bash
npm ci
cp .env.example .env.local
# .env.local에 교사 비밀번호(12자 이상), 세션 비밀키(32자 이상)를 입력합니다.
npm run dev
```

`http://localhost:3000/teacher`에서 교사 비밀번호로 로그인 → 새 과제 → 학생 참여 링크 복사 → 학생은 별도 브라우저/기기에서 작성합니다. 별명 사용을 권장합니다.

```bash
npm run typecheck
npm test
npm run build
npm start
# 브라우저 통합시험
npx playwright install chromium
npm run test:e2e
```

브라우저 실행 파일이 이미 있다면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium npm run test:e2e`를 사용할 수 있습니다.

## 구현된 사용 흐름

- 교사 로그인, 과제 생성, 배움 목표·내용 기준, 4가지 AI 사용정책, 최소 읽기 기준, 성찰질문.
- 학생 참여 링크 → 과제 안내 → 글쓰기. 내 과제 / 제출한 과제 / 피드백·다시쓰기 / 나의 과정.
- Tiptap 편집기: 제목, 서식, 크기, 정렬, 목록, 들여쓰기, 표 편집, 이미지, 링크, 인용, 실행 취소/다시 실행, 찾기, 문단 이동.
- 변경 transaction 기반 이벤트, 한글 composition 묶음, 체크포인트 버전, IndexedDB 복구본, 변경분 서버 동기화, 충돌 감지.
- 노력 기록·자료 첨부 → 화면 맨 아래 제출 확인 → 접수 완료. 제목·본문이 필요하며 노력 근거는 과제에서 평가에 포함한 경우 필수입니다. 선택 대목과 성찰은 선택 사항입니다.
- 교사 목록의 종합점수·검색·정렬·피드백 상태 필터, 전체 글 먼저 읽기, 내용 기준별 읽기 후보·앞뒤 맥락, 다섯 가지 과정 증거, 타임라인, 1/5/20/50배 리플레이, 문서 버전.
- 외부 텍스트의 문자 단위 잔존·삭제·겹친 수정 통계. 문단 이동 등 불확실한 경우 추정 표시.
- 최소 읽기 확인을 서버에서도 검사하고, 본문 인용·강점의 이유·다음 수정 한 가지를 학생에게 전달. 중간 저장한 교사 메모는 비공개.
- 학생은 피드백을 읽고 한 대목 다시쓰기·수정 이유 또는 질문을 저장. 교사는 후속 시도를 읽고, 제출 원문은 그대로 보존.
- 기록 JSON 및 학생 글 텍스트 다운로드.

## 과제 유형과 교사 확정 평가

- 새 과제에서 활용 목적과 8개 과제 유형을 선택합니다. 유형·배움 목표를 반영한 추천 배점으로 바로 게시하거나, 포함/참고/제외·고정 배점·공통 항목·교사 직접 항목(최대 3개)을 조정합니다.
- 자동 배분은 미리보기 후 적용하며, 서버도 합계 100점을 검증합니다. 점수 없는 피드백 방식도 지원합니다.
- 게시한 유형과 기준은 고정되고 학생 참여 시 평가표를 함께 보관합니다. 학생은 안내와 작성 화면에서 같은 기준을 확인합니다.
- 유형별 본문 양식, 조사·관찰용 표, 발표 구성 카드를 기존 문서 편집기로 제공합니다. 학생이 쓴 내용과 수정 이력을 보존합니다.
- 노력의 증거가 제외되면 필수 입력과 제출 검증에서도 제외합니다. 일반 과제 첨부는 노력 자료와 별도로 받습니다.
- 제출 후 교사가 항목별 점수·근거를 입력하고 읽기·피드백·최종 확인을 완료해야 평가가 공개됩니다. 교사 직접 항목과 과정 증거는 자동으로 점수를 채우지 않습니다.
- 새 평가표의 점수와 기존 과정기록 종합점수는 구분합니다. 기존 과제에는 기존 동작을 유지합니다.

선택 AI 연결: PROOFWRITE_AI_API_KEY와 PROOFWRITE_AI_MODEL을 모두 설정하면 교사 검토 시 원문 기반 초안을 생성합니다. 설정이 없거나 응답 검증에 실패하면 기본 읽기 안내임을 명시하며 AI 분석으로 표시하지 않습니다. 학생 내용은 지시가 아닌 검토 자료로 처리하고, 본문 인용과 항목별 배점 범위를 서버에서 확인합니다. 교사 직접 항목·과정 증거·즉석 대응은 AI 채점에서 제외합니다. 최종 평가는 항상 교사가 확인합니다.

API 형식 참고: https://developers.openai.com/api/docs/guides/structured-outputs

## 운영 범위

현재 배포 단위는 **교사 비밀번호 하나 / 한 학급 수준의 단일 Node 프로세스 Pilot**입니다. `.data` 또는 `PROOFWRITE_DATA_DIR`에 실제 파일을 저장하므로 **영속 볼륨이 필수**입니다. 다중 인스턴스·서버리스의 임시 디스크에는 그대로 배포하지 마십시오.

학교 운영 전 기관 계정/SSO, 다중 교사 권한, 계정 복구, 보관·삭제 정책, 실제 기기/한국어 IME/보조입력 검증, 백업·복구 훈련이 필요합니다. 자세한 절차는 [운영 안내](docs/PILOT_RUNBOOK.md), 정확한 구현/검증 범위는 [점검표](docs/IMPLEMENTATION_AUDIT.md)를 참고하세요.

## 점수와 개인정보

ProofMe는 1·2·3·5의 자동 작성 기록과 4의 학생 제공 근거를 구분합니다. 기존 과제의 교사 목록과 증거 탭에서 과정기록 종합점수(0–100)를 확인할 수 있습니다. 새 평가표를 게시한 과제에는 교사가 확정한 평가 점수를 표시합니다. 기존 기획의 시범 가중치 30/25/20/15/10을 사용하며 계산 근거·한계를 함께 표시합니다. 리듬 미참여·표본 부족은 해당 없음으로 제외하고 나머지 75점을 100점으로 환산합니다. 다섯 증거의 관찰 자료와 학생이 제시한 노력은 별도로 함께 읽습니다. 점수는 성적이나 본인 작성 확률이 아닙니다. [산정 기준](docs/PROOF_SCORE.md)을 확인하세요. 자세한 흐름·측정 정의·제한은 [ProofMe 기획과 구현](docs/PROOFME.md)을 확인하세요.

세부 타이핑 습관 비교는 선택 참여입니다. 일반 입력과 한글 등 조합 입력의 간격을 분리하고, 유효한 이전 제출 기록(같은 브라우저 권한·같은 별명·다른 과제·기록 참여·동일 입력 방식)이 있으면 자동 비교합니다. 없으면 현재 과제의 전·후반을 비교합니다. 유사도는 본인 작성 확률이 아닙니다.

브라우저 이벤트는 사용자가 조작할 수 있습니다. 서버의 순서·재생 검증은 손상·충돌을 검출하지만 작성자 신원이나 클라이언트가 정직함을 증명하지 않습니다. 교사는 반드시 글을 직접 읽습니다.

교사 관점의 구체적인 비평·가상 글 수정 예시·반영 내용은 [교사 관점 검토](docs/TEACHER_REVIEW.md)에 정리했습니다.
